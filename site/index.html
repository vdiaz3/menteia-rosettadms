El problema

Una red de dealers, decenas de DMS y nadie ve la foto completa

Cada grupo distribuidor eligió su DMS hace años. Hoy la marca no puede ver en tiempo real lo que pasa en sus talleres, mostradores y pisos de venta, y el cliente final es quien termina pagando esa fragmentación.

Cómo funciona

Dos formas de conectar el DMS. Un cerebro que lo concentra todo.

Cada dealer se conecta con el mejor método disponible para su DMS. Lo que llega de cualquier método se traduce al mismo modelo de datos dentro del cerebro central, y desde ahí se distribuye a la marca y a los canales del cliente.

Conector API

Cuando el DMS tiene API, la usamos

Algunos DMS modernos ofrecen API REST o SOAP, exportaciones programadas o SFTP. En esos casos nos conectamos directo, que es lo más rápido y lo más estable.

  1. El dealer o su proveedor nos da credenciales de API con el alcance que defina.
  2. Usamos un adaptador ya construido para ese DMS o configuramos uno nuevo.
  3. Sincronizamos de forma incremental cada hora o en tiempo real con webhooks.
  4. Las escrituras (citas, reservas de partes) también van por API, con validación previa.
Ideal para: DMS en la nube, plataformas con API pública o dealers que ya exportan reportes automáticamente.
Conector Computer Use

Cuando no hay API, un agente opera el DMS

La mayoría de los DMS en México no tienen API abierta. Ahí un agente de IA entra con un usuario dedicado y usa el sistema como lo haría un asesor: ve la pantalla, navega menús, descarga reportes y captura citas.

  1. El dueño del DMS crea un usuario con los permisos que decida (lectura, o también citas).
  2. El agente corre en un escritorio virtual aislado y graba cada sesión.
  3. Sigue un playbook del DMS: qué pantallas abrir, qué reportes bajar y cómo leerlos.
  4. Si la pantalla cambia, el agente se adapta por visión y el playbook se actualiza.
Ideal para: DMS de escritorio, terminales legadas, Citrix/RDP y desarrollos propios.

Modo híbrido y selección automática

En el alta del dealer detectamos qué ofrece su DMS. Si hay API, se usa para lo que cubra, y el agente de computer use completa lo que la API no expone (por ejemplo, reportes de taller o la agenda). El resultado es el mismo para la marca: un solo flujo de datos, con el mismo esquema y la misma frecuencia.

IA, MCP y automatización

Hecho para que agentes de IA trabajen con toda tu red

RosettaDMS expone la red completa como herramientas MCP (Model Context Protocol). Cualquier agente compatible, ya sea tu bot de WhatsApp, tu call center con IA o un asistente interno, puede consultar y actuar en cualquier dealer sin saber qué DMS usa.

Herramientas MCP disponibles

Un solo servidor MCP para toda la red. Cada llamada se resuelve contra el DMS del dealer correcto.

buscar_disponibilidadHorarios libres por dealer, código postal o VIN, según la capacidad real del taller.
agendar_citaCaptura la cita en el DMS del dealer y devuelve el folio.
estatus_ordenEtapa actual de la orden de reparación y la hora estimada de entrega.
existencia_parteExistencia por número de parte en el dealer y en dealers cercanos.
inventario_unidadesUnidades en piso por modelo, versión y color, con opción de apartar.
historial_vinServicios, fallas y campañas pendientes del vehículo en toda la red.

Preguntas frecuentes

Lo que nos preguntan marcas y dealers

¿Cuándo usan API y cuándo computer use?

Siempre que el DMS ofrezca una API o exportación automatizada, la usamos porque es más rápida y estable. Si no existe o no cubre todo lo necesario, el agente de computer use opera la interfaz del DMS. Muchos dealers terminan en modo híbrido.

¿Necesito que mi proveedor de DMS haga algo?

Con computer use, no: el agente usa el DMS con un usuario normal, como un empleado. Con API, solo se necesitan las credenciales. Recomendamos que el dealer revise las condiciones de su licencia respecto a usuarios adicionales o automatizados.

¿Cuánto tarda en conectarse un dealer?

Si su DMS ya tiene playbook o adaptador, minutos. Si es un DMS nuevo, el agente lo mapea normalmente en uno o dos días, y a partir de ahí cualquier dealer con ese DMS se conecta al instante.

¿Qué pasa si el DMS cambia de versión o de pantallas?

El agente trabaja con visión, no con coordenadas fijas. Detecta el cambio, se adapta y actualiza el playbook. Si algo requiere intervención, operaciones recibe una alerta antes de perder una sincronización.

¿Por qué es gratis para el dealer?

Porque el principal beneficiario de la visibilidad de la red es la marca, que es quien contrata la suscripción. El dealer gana citas, piezas a tiempo y menos captura sin poner un peso.

¿Qué es MCP y por qué importa?

Model Context Protocol es un estándar abierto para que los agentes de IA usen herramientas externas. Con nuestro servidor MCP, cualquier agente compatible puede agendar, consultar estatus o buscar partes en toda tu red sin una integración por dealer.
